# The "pixi can help here" advisory <Badge type="tip" text="1.3" />

Outside pixi projects, PyPilot watches for walls that pip and uv cannot climb and conda-forge can. When it finds one it says so, explains why, and points at `pypilot migrate-to-pixi`. It only suggests; nothing changes until you run the migration.

## What triggers it

All signals come from data the engine already has; no extra network calls.

1. **A dependency with no installable wheel here** (sdist only, no files for this platform, or no wheel for the environment's Python) **that conda-forge builds for this platform.** The conda-forge table is curated to packages whose source build needs more than a compiler: system libraries, Fortran, nvcc, or a very long compile. About 190 packages, from GDAL, cartopy and fiona to dlib, faiss, flash-attn and pymol.
2. **A failed pip/uv build whose output names a missing header, `*-config` tool, pkg-config module or shared library.** The table maps those names to the conda-forge package that provides them.
3. **CUDA sources** (`.cu`, `.cuh`) in the repository and no `nvcc` on `PATH`, `CUDA_HOME` or `CUDA_PATH`.
4. **A repository that mixes Python with R, Rust or CMake/Meson C++** (Info only).

Nothing here runs in a pixi project; its own checks cover it.

## In the editor

With `notifications = "all"`, or when the finding is a warning, the workspace notification gains an **Initialize pixi project** button. The engine handles it the same way in Zed and VS Code: it runs a dry run, shows one message with what `pixi.toml` would contain (Python, the number of conda-forge and PyPI dependencies; `pyproject.toml` and `requirements.txt` stay as they are) and offers **Write and install**, **Write pixi.toml** or **Cancel**. Nothing is written before you choose. The same message follows the button on the toast after a pip/uv build fails on a system library conda-forge ships. The VS Code palette command works differently (full preview first); see [From the editor](./migrate#from-the-editor).

## Where the data comes from

`helper/data/conda_forge_packages.json` is generated by `scripts/gen_conda_forge.py` from [prefix.dev](https://prefix.dev/api/graphql) and [parselmouth](https://github.com/prefix-dev/parselmouth) (the PyPI-to-conda name mapping). For each package it records the conda-forge name, version, the platforms and Pythons it is built for, the system libraries it bundles and why the source build is hard. Like every data table it is refreshed from `main` on installed engines; see [Data tables](/reference/data-tables).
